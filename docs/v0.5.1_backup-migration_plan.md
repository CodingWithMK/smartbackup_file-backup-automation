# Implementation Plan: Backup Migration & True Sync (v0.5.1)

## Problem
The current migration logic from legacy layout to per-device subfolders is fragile and crashes if files disappear or conflict. Additionally, the backup program does not synchronize deletions (files deleted on MacBook remain in the backup), and type changes (file to directory) cause "data collisions" that result in `FileNotFoundError` or `FileExistsError`.

## Proposed Fixes

### 1. Robust Migration (`src/smartbackup/core/engine.py`)
- Wrap `item.rename` in `_migrate_legacy_layout` with `try...except (FileNotFoundError, OSError)`.
- Log warnings for skipped files instead of crashing.

### 2. Implementation of "Hard Sync" (`src/smartbackup/core/engine.py`)
- Uncomment the deletion logic in `BackupEngine.run()`.
- Fix the logic to correctly call `self._delete_files` with absolute paths.
- Pass `deleted_paths` to `manifest_manager.update_from_backup` to ensure the manifest is synchronized.

### 3. Structural Collision Handling (`src/smartbackup/core/engine.py`)
- In `_copy_single_file`:
  - If target is a directory but source is a file: Delete target directory before copying.
  - If target parent is a file but needs to be a directory: Delete parent file before `mkdir`.

## Verification Plan
- Create a reproduction test case for file/directory collisions.
- Verify that deleted files on the source are removed from both the backup disk and the manifest.
- Verify migration robustness against missing files (e.g., `.DS_Store`).
